ADR-012 check_circle ACCEPTED

Adoption of gRPC for Internal Services

subject Context

System requires high-throughput, low-latency communication between Microservices. Current JSON/REST implementation is introducing serialization bottlenecks under peak load, and lack of strict typing is leading to integration friction between decoupled teams.

Decision

We will use gRPC with Protobuf for all internal service-to-service calls.

alt_route Alternatives Considered

  • warning
    REST / OpenAPI Rejected: Too much parsing overhead at scale; weaker client generation guarantees.
  • cancel
    GraphQL Rejected: Added complexity not needed for internal, tightly-coupled service boundaries.

balance Trade-offs

Performance (+)
Strong Typing (+)
Browser Support (-)
Complexity (-)

Consequences

  • Requires code generation step in CI/CD
  • Improves telemetry and tracing out-of-box
